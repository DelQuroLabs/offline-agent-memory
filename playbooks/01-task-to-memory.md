# One task from intake to memory

1. Coordinator creates a task contract with one scope and acceptance checks.
2. Operator generates and inspects a packet for the chosen specialist.
3. Specialist produces the artifact and distinguishes evidence from assumptions.
4. Reviewer checks the artifact against the original task and available evidence.
5. Specialist revises only the identified issues, then stops when the contract is met.
6. Steward proposes a few durable memories, with sources and classifications.
7. Operator checks the proposals and activates those worth retaining.
8. Save the result and next step in the project folder.

Example: a software task fixes a parsing error. Keep the fix in the project, the reproduction log in sources, the tradeoff in decisions, and the general prevention lesson as a reviewed memory. Do not store all debugging chatter as active knowledge.

Failure handling: if evidence is missing, report the gap; if the result is disputed, preserve alternatives; if the task crosses scopes, create separate tasks and a reviewed handoff.
