# Memory governance

## Responsibilities

The task specialist produces work. The Reviewer checks the result. The Memory Steward proposes durable records. The owner or a specifically delegated operator activates and shares memory. The Archivist proposes retention and backup actions. One person may perform these roles, but the review steps remain distinct.

The tools record the reviewer string supplied by the operator. They do not authenticate identity or guarantee that review occurred. Keep write access operator-controlled and use an independent protected version history if accountability requires it.

## Promotion checklist

1. Is this useful for a future task?
2. Does the wording match the actual evidence?
3. Is the source sufficient and locatable?
4. Is the scope the narrowest appropriate one?
5. Is sensitivity classified correctly, including excerpts and metadata?
6. Does an existing record already cover this?
7. Is there a conflict or replacement to resolve?
8. Is the review interval appropriate to how quickly the claim changes?

All eight checks should have an answer before activation. Shared memory needs an additional destination review: all three domains can read it.

## Change discipline

Preserve IDs and history. Use a new ID when a claim's meaning changes materially. Use `supersedes` for explicit same-scope corrections and deprecate the replaced record after activation. Do not silently “clean up” evidence that makes a record less certain.

Do not let repeated model suggestions accumulate as active facts. Drafts can be archived when they are speculative, redundant, too broad, or not useful. A small collection of reliable records is more valuable than a large collection of plausible prose.
