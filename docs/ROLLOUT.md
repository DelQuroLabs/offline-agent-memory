# A 30-day rollout

## Days 1–3: establish the boundaries

Read START_HERE, choose one real task in each domain, and use Coordinator → Specialist → Reviewer. Confirm local inference works offline. Keep the source collection small and curated. Write an owner profile with explicit preferences only; no inferred personality labels.

Success: you can retrieve a known record, explain its source, and show that another domain's record is absent from the context packet.

## Days 4–7: capture useful memory

Add a handful of preferences, procedures, and decisions that you repeatedly need. Review each before activation. Keep entire transcripts in sources or sessions only when necessary. Complete one task end to end and record what the reviewer corrected.

Success: a later task benefits from an earlier decision without rereading the entire session.

## Days 8–14: standardize work

Use task and handoff templates. Adopt one playbook per domain. Add evaluation cases drawn from real failures. Check retrieval with alternate wording and tags. Resolve duplicates before adding more roles.

Success: the same task can be repeated with a different local model and comparable evidence-based outputs.

## Days 15–21: improve quality

Review overdue records, conflicting claims, and unnecessary sensitive data. Test a backup restore into a separate folder. Record model/runtime settings used in each experiment. Assess whether role boundaries reduced confusion or added overhead.

Success: you can restore the repository and regenerate the same kind of context packet using only local assets.

## Days 22–30: expand deliberately

Add new project areas, then specialist variants only when needed. Consider an embedding index only if keyword retrieval repeatedly fails on measured cases. Consider automation only after manual workflows and permissions are understood. Keep the readable files as the source of truth even if an index is added.

Success: you have a small set of trusted active memories, a useful source library, and repeatable procedures in all three domains. Volume is not the goal; reliable reuse is.
